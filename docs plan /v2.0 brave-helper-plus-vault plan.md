# V2.0 Plan — Local Brave Helper + Vault

## Summary
V1.6 establishes the right product shape: a **local-only Brave helper extension** with a side panel and local Ollama.

V2.0 extends that helper into a more practical daily-use tool by adding:
- a local password / profile vault
- guided autofill with source tracing
- screenshot capture
- lightweight history and memory

The product is still:
- local-only
- unpacked in Brave
- not published for everyone
- confirmation-first for risky actions

## V2.0 goals
Build a helper that can:
- remember site credentials and profile details locally
- tell the user where each autofill value came from
- fill fields only after confirmation
- capture screenshots on request
- keep a simple history of chats, captures, and actions

## Product rules
- No silent fill, submit, send, pay, or delete actions.
- No invented personal data when a value is missing.
- Every filled value must show a source before execution.
- Screenshots must be user-triggered.
- Sensitive data stays local on the device.

## Scope

**In**
- Local vault for passwords and profile data
- Per-field autofill preview with source labels
- Screenshot capture of the visible tab
- History for chats, page snapshots, screenshots, and executed actions
- Basic search over saved history

**Out**
- Cloud sync
- Shared accounts / multi-user mode
- Silent social posting
- Fully autonomous browsing
- Background monitoring of all tabs

## Main features

### 1. Local vault
Store the following locally:
- login items: site, username, password, notes
- profile items: full name, email, phone, address, custom fields
- optional per-site overrides

Suggested storage shape:
- `vaultProfiles`
- `vaultLogins`
- `vaultSiteOverrides`

### 2. Guided autofill
Autofill should work like this:
1. User presses `Analyze form` or asks to fill.
2. Content script extracts visible inputs with labels, names, types, and stable selectors.
3. Side panel shows a fill plan:
   - target field
   - proposed value
   - source of value
   - missing fields
4. User confirms.
5. Extension fills only confirmed fields.

When data is missing:
- show `Missing`
- ask the user to provide a value or save one to the vault
- never guess personal details

Example source labels:
- `profile.default.full_name`
- `login.example.com.username`
- `siteOverride.github.com.email`
- `userProvidedThisSession.phone`

### 3. Password vault behavior
V2.0 is a simple local vault, not a full replacement for dedicated password managers.

Minimum expected behavior:
- add, edit, delete vault entries
- lock / unlock vault in the current session
- copy username / password manually
- use credentials for guided fill

Recommended security baseline:
- encrypt vault contents locally before storage
- derive the encryption key from a user master password
- auto-lock after inactivity
- require unlock before revealing secrets or filling passwords

### 4. Screenshot capture
Allow the helper to:
- capture the visible tab screenshot on explicit request
- save screenshot metadata in history
- optionally attach the screenshot to the current chat context

V2.0 screenshot rules:
- only capture on user request
- clearly show that a screenshot was taken
- do not auto-send screenshots anywhere

### 5. History and memory
Add lightweight persistence so the helper remembers prior activity.

Persist locally:
- chat sessions
- page snapshots
- executed actions
- screenshots metadata
- vault usage events

Useful memory behaviors:
- reopen previous chats
- show recent pages
- show what fields were filled and from where
- search by site, title, or date

## Architecture

```
manifest.json
src/
  background/
    index.ts              service worker
  content/
    index.ts              page snapshot + form extraction + fill + highlight
  sidepanel/
    SidePanel.tsx         chat, history, vault, autofill review
  lib/
    ollama.ts             local streaming chat
    page.ts               sidepanel <-> content messaging
    vault.ts              encryption + vault access helpers
    history.ts            persistence helpers
  store/
    index.ts              messages, snapshot, vault state, history state
```

## Data model

Suggested local stores:
- `chatSessions`
- `chatMessages`
- `pageSnapshots`
- `actionHistory`
- `screenshots`
- `vaultProfiles`
- `vaultLogins`
- `vaultSiteOverrides`
- `settings`

Suggested fields for action history:
- timestamp
- tab URL
- action type
- target selector
- previewed values
- confirmed values
- source labels
- result

## Phases

### Phase 1 — Persistence foundation ✅ Done
- Add local persistence for chat, snapshots, and action history.
- Restore the last side-panel session after reload.
- Add a History tab.

**Done when**
- Closing and reopening Brave keeps chat and recent page history.

### Phase 2 — Structured form extraction ✅ Done
- Extend content script to extract visible form fields with labels and selectors.
- Add `Analyze form` flow in the side panel.
- Show missing vs matched fields.

**Done when**
- The helper can inspect a form and build a readable fill plan without mutating the page.

### Phase 3 — Vault ✅ Done
- Add local vault storage for profiles and logins.
- Add lock/unlock flow.
- Add CRUD UI in the side panel.

**Done when**
- The user can save credentials and profile data locally, lock the vault, and unlock it later.

### Phase 4 — Confirmed autofill ✅ Done
- Connect form analysis to vault/profile data.
- Show source labels for every proposed value.
- Fill only confirmed fields.

**Done when**
- The user can review exactly where each value came from and then fill the selected fields.

### Phase 5 — Screenshots ✅ Done
- Add visible-tab screenshot capture.
- Save screenshot metadata into history.
- Allow attaching a screenshot to the current chat.

**Done when**
- The user can request a screenshot, see it in history, and reference it in chat.

## Safety guardrails
- No fill without review.
- No password reveal without unlock.
- No send / submit / delete automation in V2.0.
- No fake values for unknown fields.
- No screenshot capture without a user action.
- Keep a visible log of what the helper did.

## Recommended UX
- Tabs in side panel:
  - Chat
  - History
  - Vault
  - Form Fill
  - Settings

- Autofill review card should show:
  - field label
  - proposed value
  - source label
  - editable override
  - include / skip toggle

## Setup
1. Load the unpacked extension in Brave.
2. Run Ollama locally.
3. Create a master password for the vault on first use.
4. Add at least one profile and optional site login.
5. Use `Read page`, `Analyze form`, `Fill selected`, or `Take screenshot`.

## Non-goals
- Replacing Brave's native UI
- Replacing a mature password manager feature-for-feature
- Running for everyone as a public extension
- Cloud-based AI processing

## Success criteria
- The helper reads pages and answers questions locally.
- The helper can analyze a form and produce a trustworthy fill plan.
- The user can see where every autofill value came from.
- The helper can store local credentials and profile data securely enough for personal use.
- The helper remembers useful history across restarts.
