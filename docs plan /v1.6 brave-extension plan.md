.# V1.6 Plan — Local Brave Helper Extension

## Pivot summary
V1.5 / V1.5-lean built a "Local AI Studio" web app (RAG over local PDFs, in-browser embeddings, WebLLM provider, Ollama provider). Useful as a learning artifact — wrong shape for the actual product.

V1.6 reshapes the repo into a **local-only Brave (Chromium) helper extension**:
- Loaded as an unpacked extension on the developer's own machine.
- UI lives in a **side panel** (not a popup) — chat-sized, sits beside the page.
- Reads the active tab via a content script.
- Talks directly to a **local Ollama** (`http://localhost:11434`).
- Not published to a web store.

## Why side panel, not popup
- Popup is too small for chat, summaries, extracted entities, action confirmations.
- Side panel feels like an assistant beside the page — survives tab switches and clicks.
- Easier to surface form-fill / click previews and confirmation UI without modal awkwardness.

## V1 scope (this plan)
**In:**
- Side panel UI in Brave / Chromium.
- Read current tab content (title, URL, visible text, flat link list).
- Summarize page.
- Q&A about the page.
- Extract links, prices, dates, emails.
- Streamed responses from local Ollama.
- **Slash Commands**: `/start`, `/clear`, `/summary`, `/takeSS`, `/save`.
- **Session Actions**: Clear chat button, manual page re-sync.
- **Tab Screenshot**: Capture visible tab (`/takeSS`).
- **Local Save**: Save page snapshots to extension storage (`/save`).

**Out (deferred):**
- Auto-fill / auto-click without confirmation.
- Auto-post to WhatsApp / Instagram / any social.
- Modifying Brave's top bar, tabs, or native UI.
- Full autonomous browsing.
- WebLLM in-browser fallback (V1.5 idea — re-add only if needed).
- Local document RAG (the Studio feature — re-add only if needed).

## Architecture

```
manifest.json                MV3, side_panel, host_permissions, scripting, activeTab
src/
  background/index.ts        service worker — opens side panel on action click, message router
  content/index.ts           DOM reader (innerText, links), highlight helper, action executor
  sidepanel/
    index.html
    main.tsx
    SidePanel.tsx            chat UI (small, no docs/RAG)
  config/
    models.ts                high-context model safety (num_ctx) & custom system prompts
  lib/
    ollama.ts                streaming /api/chat (carried over from V1.5)
    page.ts                  message helpers between side panel and content script
    session.ts               screenshot capture & local page storage
  store/index.ts             slim Zustand: messages, model, current tab snapshot
```

### Tooling choice
- **`@crxjs/vite-plugin`** for MV3 + Vite multi-entry. Standard, removes manifest/HMR footguns.
- React + TypeScript + Tailwind kept from V1.5 for the side panel UI.
- Zustand kept for state.

### High-Context Model Safety
To prevent Ollama crashes on machines with 16GB RAM while using high-context models (`Gemma 4 26B` / `E4B`), the extension uses safe `num_ctx` defaults:
- **Gemma 4 26B**: 65,536 active context (supports up to 256K max).
- **Gemma 4 E4B**: 32,768 active context (supports up to 128K max).

The UI displays the active budget to ensure the user knows the current session's reliability limit.

### Page-reading strategy (V1)
**Simple** — content script returns:
- `document.title`
- `location.href`
- visible text (`document.body.innerText`, truncated)
- flat list of links (`href` + visible text)

This is enough for summarize / Q&A / extract.

### Page-reading strategy (V2 — when actions land)
**Structured** — simplified accessibility tree (headings, links, buttons, inputs with stable selectors). Needed once we wire up reliable click/fill so the LLM can ground actions in real elements.

## Trust & safety guardrails (day one)
- Any action feature (`fillField`, `click`) must require **explicit confirmation** in the side panel before executing — no silent actions.
- Highlight target elements before action.
- Keep a visible history of executed actions in the side panel.
- No auto-submit. No payment / send / delete actions in V1.

## Setup (developer)
1. `npm install`
2. `npm run build` — produces `dist/`.
3. In Brave: `brave://extensions` → enable Developer mode → Load unpacked → select `dist/`.
4. Run Ollama with `OLLAMA_ORIGINS=chrome-extension://*` (or specific extension ID once known) so the extension can fetch `localhost:11434`.
5. Pull a model: `ollama pull llama3.1:8b-instruct` (or similar).

## Out of scope for V1.6
- Multi-tab simultaneous context.
- Saved sessions / persistence beyond live side-panel state.
- Cross-device sync.
- Marketplace / Chrome Web Store packaging.

## What carries over from V1.5

- Zustand store skeleton (slimmed: drop documents, conversations DB, scopes, embeddings status).
