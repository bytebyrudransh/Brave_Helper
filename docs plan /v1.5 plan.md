# AI Browser V1.5 Plan: Advanced Local AI Studio & Agentic Browser

## 1. Context & Architectural Review
A comprehensive review of the current architecture (V1) by multiple AI models (ChatGPT, Claude, Gemini) yielded a unanimous consensus: **The current React + Express + Puppeteer architecture is a prototype and not suitable for a production-grade product.**

### The Core Issues:
- **Fragility:** Puppeteer is meant for headless testing, not human co-browsing. It desyncs easily when the user interacts with the browser manually.
- **Inadequate Page Context:** Relying on `document.body.innerText` capped at 15k characters is insufficient for reliable AI actions. The AI needs structured DOM data (bounding boxes, ARIA roles, visible elements).
- **State Management:** Prop-drilling in React is breaking down. A robust store (like Zustand) is required for multi-tab sessions, streaming chats, and history.
- **Identity Crisis:** The project is currently torn between three visions:
  1. An agentic browser assistant.
  2. A local in-browser AI demo gallery.
  3. A premium Local AI Studio.

## 2. The V1.5 Vision: Hybrid Local AI Studio
V1.5 resolves this identity crisis by pivoting to an **Advanced Local AI Studio** that integrates safely and robustly with a **Browser Assistant**. 

Instead of a fragile Node/Puppeteer middleman, we will build a premium client-side application for the AI Studio, and handle browser automation through a proper, secure channel (Extension or Electron).

### Key Pillars of V1.5

#### A. The Local AI Studio (Frontend-First)
- **Immersive UI/UX:** A high-end, premium interface built with React 19, Vite, and Tailwind v4.
- **Hybrid Inference Architecture:**
  - **In-browser:** WebLLM, Transformers.js (for WebGPU/WASM local inference without a server).
  - **Desktop/Local:** Direct fetch calls to Ollama for heavier models, bypassing the Express proxy.
- **Local RAG & Memory:** Persistent document chat and embeddings stored locally in IndexedDB.
- **Global State:** Complete refactor to use **Zustand** for managing chat sessions, active tabs, and model states.

#### B. The Agentic Browser Re-architecture
To fulfill the "browser control" promise without the Puppeteer desync issues, we will transition to one of two production-grade architectures:
- **Path A: Browser Extension (Recommended):** The Local AI Studio communicates with a Chrome/Brave Extension. The extension natively and securely reads the DOM, highlights elements, and executes AI-planned actions.
- **Path B: Electron/Tauri App:** The Studio and the Browser are bundled together in a single desktop application using `BrowserView`.

#### C. Safe & Structured Action System
- **Structured Page Extraction:** Send the LLM a simplified, structured accessibility tree (headings, links, buttons, inputs) rather than raw text.
- **Strict Action Protocol:** The AI must output JSON action plans (`click`, `fill`, `navigate`, `extract`).
- **Visual Grounding & Confirmation:** The UI must highlight the target element on the screen and require user confirmation before executing any destructive or high-risk actions.

## 3. Migration Roadmap

### Phase 1: Stabilize & Shift to Studio
- Archive conflicting plan docs to establish this V1.5 plan as the single source of truth.
- Lift existing React state into Zustand.
- Implement streaming for Ollama responses to immediately improve UX.
- Remove the Node.js Express server dependency for Ollama; make requests directly from the frontend.

### Phase 2: Build the Core Studio Features
- Implement Web Workers for in-browser model loading (Transformers.js / WebLLM) so the main thread remains unblocked.
- Set up IndexedDB for persisting chat history and RAG embeddings.

### Phase 3: Implement the New Browser Bridge
- Discard the Puppeteer backend.
- Scaffold a basic Browser Extension (Manifest V3) with a Content Script to extract structured DOM data (`PageSnapshot`).
- Connect the Extension to the Local AI Studio to allow the AI to read real-time, accurate page state.

### Phase 4: Action Execution
- Define the typed `ProposedAction` schema.
- Update the Extension to visually highlight elements based on the AI's intended actions.
- Add the confirmation UI in the Studio before the Extension executes the action.

## 4. Minimum Production Rules
1. **No silent destructive actions** (submitting, paying, deleting).
2. **No action without a visible target.**
3. **No unstructured DOM guessing.**
4. **No memory-only architecture for sessions.** 
5. **No hardcoded local executable paths.**
